## 5. 真机全流程验证

后端 85 个用例跑在**模拟数据库**上，以下行为只有在真实云环境里才能确认。建议用两个微信号（A、B）操作，任何一步报错，把云函数日志里的第一行错误发出来。

**账号与打卡**
- [ ] A 首次进入：提示 10、体力 25
- [ ] 每日打卡：提示 +3、体力 +5；当天再点提示"已打卡"
- [ ] 「我的」页设置头像和昵称，保存成功；再换一次头像，云存储里的旧头像文件被删掉
- [ ] 昵称填敏感词，保存被拒绝

**闯关**
- [ ] 第一次点「开始挑战」先弹玩法说明，确认后体力 −1
- [ ] 中途退出再进来，体力不再扣
- [ ] 答错一次扣一颗心；答错 3 次显示「挑战失败」，「再来一次」体力 −1，已揭开的字还在
- [ ] 使用提示：提示 −1，揭开一个字；同一关第 4 次提示被拒绝
- [ ] 答对：显示释义和出处，下一关解锁
- [ ] 通过第 10 关：解锁宝箱，打开得提示 +2、体力 +3；称号晋升为「童生」

**道具不足**
- [ ] 控制台把 A 的 `users.items.stamina` 改成 0：开始挑战时先引导打卡（如果当天还没打卡）
- [ ] 已打卡后体力仍为 0：提示"N 分钟后恢复 1 点"
- [ ] 把 `items.hint` 改成 0 并点提示：弹出求助面板

**求助**（重点验证事务和并发）
- [ ] A 在某关开始挑战后发起求助，分享给 B
- [ ] B 点开卡片看到题目、看不到答案，显示"还有 3 次答错机会"
- [ ] B 答错 3 次后被锁定
- [ ] 换一条求助让 B 答对：A 回到大厅弹出「B 帮你解开了第 N 关」，A 的这一关直接通过
- [ ] B 当天帮 A 解开第 3 关时被拒绝（每天最多 2 关）
- [ ] A 先自己答对，B 再点开卡片：显示「TA 已经自己解开这一关啦」

**通关、统计、排行榜**
- [ ] 控制台把 A 的 `progress` 中 `solved` 改成 1–999、`currentLevel` 改成 1000，然后通过第 1000 关：过关页显示「恭喜通关全部 1000 关」，`completions` 里多一条记录
- [ ] 管理员打开「数据统计」：通关用户、总用户、通关率的数字正确；非管理员看不到入口
- [ ] 排行榜：A、B 的名次和通关数正确；B 不在前 100 名时底部显示自己的名次

**定时任务与配置**
- [ ] 控制台手动测试触发器 `cleanupExpiredRecords`：返回各集合的删除数量，没有报错
- [ ] 手动测试触发器 `snapshotStats`：`stats_daily` 里出现当天的记录
- [ ] 在 `game_rules` 里把某个数值故意改成字符串（如 `"level": {"staminaCost": "2"}`）：日志出现 `[rules] invalid config fields`，游戏仍按默认值 1 扣体力；测完改回来
